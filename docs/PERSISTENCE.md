# 设置与播放进度的保存原理（NEWFWLOG.TXT）

## 现象

重启后出现以下情况，通常是同一个原因：

- 界面语言回到英文
- 亮度、“开机时”等设置回到默认值
- “继续播放 / 从暂停处继续”不生效，开机停在文件浏览

## 原因

固件**没有**独立的配置分区，也**不会**创建或修改文件。设置和播放进度都保存在
内部存储根目录的 `NEWFWLOG.TXT` 里，该文件的**最后一个扇区（512 字节）**用作状态区：

| 字（32 位） | 内容 | 代码 |
|---|---|---|
| 0–63 | 播放进度：文件夹、选中项、曲目、位置、音量、播放模式、ReplayGain 模式 | [resume.c](../fw/src/resume.c) |
| 64 起 | 设置：屏幕、亮度、语言、开机行为等，带版本魔数和校验和 | [settings.c](../fw/src/settings.c) |

文件的其余扇区是循环日志（[log.c](../fw/src/log.c)）。当文件至少 32 KiB 时，状态扇区之前另留出 16 个扇区给界面数据；收藏功能目前使用其中 8 个扇区，可保存最多 64 首歌曲。收藏记录文件卷、起始簇、大小、歌曲名，以及 TF 卡卷序列号。没有合适的日志文件时，设置/进度不会保存，收藏功能也不可用。

这些区域都位于**预先存在的 `NEWFWLOG.TXT` 内**，写入受 `emmc_write_log()` 范围围栏约束；不会分配文件、修改目录或 FAT 分区表。循环日志容量相应减去预留扇区。

**如果根目录没有这个文件，或者文件不合格，状态区不存在，所有保存都会跳过**，每次开机都使用默认值（英文、开机进入文件浏览）。

## 为什么固件不自己创建

出于安全，固件对 eMMC 的写入有三道围栏（[emmc.c](../fw/src/emmc.c)）：

1. 安装器：只能写固件区。
2. USB 磁盘读写模式：只能写用户分区（由电脑主机操作）。
3. `emmc_write_log()`：**只能改写 `NEWFWLOG.TXT` 已有的扇区**。

保存设置属于第 3 种。它不分配簇，也不改 FAT 表和目录，所以即使保存时断电，
也不会损坏你的音乐文件系统。代价是文件必须由电脑预先创建好。

## 文件要求

- 位置：内部存储根目录，文件名 `NEWFWLOG.TXT`
- 大小：8 KiB 到 16 MiB
- **连续存放**，不能有碎片
- 固件在 USB 模式期间不写这个文件，退出 USB 模式后会重新查找

任一条件不满足，`log_attach()` 失败（错误码：-1 无文件，-2 碎片，-3 大小不合规），
日志里会记录 `log: not written to the volume: ...`。

## 创建方法

在电脑上运行 [fw/tools/mklog.py](../fw/tools/mklog.py)：

```sh
python3 fw/tools/mklog.py /挂载路径            # 默认 1 MiB
python3 fw/tools/mklog.py /挂载路径 --size-kib 4096
python3 fw/tools/mklog.py /挂载路径 --force    # 替换已有文件
```

然后安全弹出并重启播放器。脚本会检查文件是否连续；若提示可能有碎片，
请清理空间，删除文件后重新创建。

## 何时保存

[`resume_save()`](../fw/src/resume.c) 在这些时机写入状态区：

- 退出设置页，以及切换语言时立即保存
- 切歌、暂停、停止、浏览目录等操作
- 播放中每 60 秒一次，拔耳机暂停时
- 关机、休眠定时器结束时

内容没有变化时（校验和相同）不会写入，减少 eMMC 磨损。

## 开机恢复

[`resume_load()`](../fw/src/resume.c) 先读取设置，再按“开机时”的选项恢复：

| 选项 | 行为 |
|---|---|
| 继续播放 | 回到上次文件夹和曲目，从约 2 秒前自动播放，并进入播放界面 |
| 从暂停处继续 | 回到上次曲目和位置，不自动播放，进入播放界面，按 PLAY 继续 |
| 文件浏览 | 只回到上次文件夹，进入文件浏览 |

以下情况会回到文件浏览：上次的文件夹或曲目已不存在（如 SD 卡被拔出、文件被移动或删除），
或曲目无法解码（显示“无法播放”）。

## 排查清单

1. 内部存储根目录有没有 `NEWFWLOG.TXT`，大小是否在 8 KiB–16 MiB。
2. 文件是否碎片化（Linux 下 `filefrag NEWFWLOG.TXT`，应为 1 extent）。
3. 用 [readlog.py](../fw/tools/readlog.py) 读日志，查看 `log:` 开头的行。

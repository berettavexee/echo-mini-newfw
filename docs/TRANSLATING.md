# Translating the interface

The interface of the firmware is written in English. Translations are in progress: they use
gettext PO files, so that they can be edited on [Weblate](https://weblate.org) or with any PO
editor (Poedit, Lokalize…). No C is needed to translate.

The steps (ETUDE §112):

1. **Done.** The strings shown on the screen are marked in the sources. The template
   `fw/po/newfw.pot` is extracted from them.
2. **Done.** The translations are packed as catalogues in the firmware image, next to the font
   (`fw/tools/mklang.py`, `fw/src/lang.c`). Only the catalogue of the chosen language is loaded.
   A string without a translation, or whose translation is flagged fuzzy, is shown in English.
3. **Done.** The Language setting (Settings, first line). French; Simplified Chinese and Japanese
   from pull request #1 by iamcheyan, with proposals for the strings added since, flagged fuzzy
   until a native speaker reviews them.
4. To do. The project is opened on Weblate.

## The files

- `fw/po/newfw.pot`: the template. Generated by `make -C fw pot`, never edited by hand.
- `fw/po/<language>.po`: one per language (`fr.po`, `zh_CN.po`, `ja.po`). A new file is a new
  language in the next image: its name in the Language setting is its translation of "English".

## For translators

- Keep each translation short. The screen is 320 × 170 pixels, with about 40 Latin characters
  or 20 CJK characters on a line. A line too long is cut, except on the play screen and in the
  selected row of a list, where it scrolls. `make check` notes the translations wider than the
  screen.
- Keep the printf conversions (`%u`, `%s`, `%%`) of a `c-format` string, in the same order
  (`make check` refuses a translation that does not).
- A fuzzy entry is not used: remove the flag once the translation is checked.
- The comments starting with `TRANSLATORS:` explain the context of a string.
- Key names (PLAY, BACK, MENU, VOL+, VOL-, Power), file names (NEWFWLOG.TXT, .IMG) and FW1/FW2
  stay as they are.
- Scripts: the font (Fusion Pixel 12 px) covers Latin, Greek, Cyrillic, Chinese, Japanese and
  Korean. Right-to-left scripts and scripts that need shaping (Arabic, Hebrew, Thai, Devanagari…)
  are not supported.

## For developers

Every string shown on the screen is marked. `make check` refuses a string passed to a drawing
function (`lcd_text`, `sys_line`, `put_str`…) without one of these marks (`fw/src/i18n.h`):

| Mark | Use |
|---|---|
| `T("text")` | Shown, translated where it is used. |
| `N_("text")` | In a table of strings. Translate it with `tr(table[i])` where it is shown. |
| `EN("text")` | Shown, but stays in English: diagnostic screens, the fault screen, units. |

- Write a whole sentence with its numbers as one format string,
  `log_format(b, end, T("Battery too low (%u %%)"), pct)`, rather than pieces put together:
  word order differs between languages.
- Put a comment `/* TRANSLATORS: ... */` on the line before a string whose meaning is not
  obvious.
- The log (NEWFWLOG.TXT) stays in English.
- After adding or changing a string shown, run `make -C fw pot` and commit `fw/po/newfw.pot`
  with the change. `make check` (and the CI) fail when the template is out of date.

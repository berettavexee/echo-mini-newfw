# CS43131: the DACs of the ECHO MINI

The SNOWSKY ECHO MINI has two Cirrus Logic **CS43131** (a DAC with its own headphone amplifier),
one per channel. This page collects how they are wired and driven, what each known firmware writes
to them, and where these sequences differ from the manufacturer's recommendations. The reference is
Cirrus Logic's public datasheet, DS1155F2 (December 2022, on
[cirrus.com](https://www.cirrus.com/products/cs43131/)); section numbers below are that document's.
The study behind this page, in French, is `ETUDE.md` §3.5 (the stock firmware), §15 (our first
sound) and §88 (audio clocks).

Status: the start-up sequence is the one of every known firmware and has played without an I2C
error since version 0.13. The output level stays at 1 V and the filter at the first one (decided
2026-11-01); the datasheet's pop-free power-down is implemented since test image 0.99e (no click heard), with
a fixed delay instead of `PDN_DONE`, which these chips never raise.

## Wiring

- **Two chips in dual mono.** Both receive the same stereo I2S frame from I2S1 of the RKNanoD; each
  keeps one channel through `ASP_CH_1_SZ_EN` / `ASP_CH_2_SZ_EN` (0x05000A / 0x05000B): `0x07` on the
  left chip, `0x0F` on the right one. The datasheet's "mono mode" (§5.12, the 0x18xxxx block below)
  is on in both, which lets each chip drive its output from one channel.
- **I2C0** of the RKNanoD, pins GPIO2_10 / GPIO2_11 (function 1), 400 kHz. 7-bit addresses `0x30`
  (left) and `0x33` (right). A write is 5 bytes: the register address (24 bits, high byte first),
  `0x01`, then the value; a read sends the first five bytes, then reads one byte.
- **Identification**: registers 0x010000-0x010005 read `43 13 10 00 a1 06` on both chips.
- **GPIOs** around the chips (roles inferred from the stock firmware and RECHO, not from a
  schematic): GPIO2_0, GPIO2_14 and GPIO2_2 set to 1 first (supplies and output switching; GPIO2_0
  at 1 silences the jacks, so it goes back to 0 once the output runs); GPIO2_1 pulsed (the chips'
  reset); GPIO1_4 set to 1 after the first `CLASS_H_CTL` write (the output stage).
- **Clocks**: the chips run from their own 22.5792 MHz crystal (`CRYSTAL_SET` = `0x02`) and are
  **slaves** of the RKNanoD's I2S (`ASP_CLOCK_CONF` = `0x0C`): 64-bit frames, 32-bit slots. The
  sample rate is set by the RKNanoD's ACODEC PLL (`ETUDE.md` §88).

## The start-up sequence

Written to both chips unless noted (`fw/src/audio.c`, `dac_setup()`). It follows the datasheet's
example "power-up sequence to I2S playback in mono mode" (§5.13.4), with a few differences listed
below.

| Step | Registers |
|---|---|
| Power and reset | GPIO2_0, 2_14, 2_2 at 1; 2 ms; GPIO2_1 at 0 (1 ms), at 1 (8 ms), at 0; 2 ms |
| Identification | read 0x010000-0x010005 |
| Output stage | `CLASS_H_CTL` (0x0B0000) = `1F`; 80 ms; GPIO1_4 at 1 |
| Crystal | `CRYSTAL_SET` (0x020052) = `02`; read `INT_STATUS_1`; `INT_MASK_1` (0x0F0010) = `E7`; `PWDN_CTL` (0x020000) = `F6` (crystal on, the rest off) |
| Serial port | `SP_BITSIZE` (0x01000C) = `04`; ASP numerator/denominator `0001`/`0008`, LRCK high time `001F`, period `003F`, `ASP_CLOCK_CONF` = `0C`, `ASP_FRAME_CONF` = `0A`; channel locations 0; `ASP_CH_x_SZ_EN` per chip |
| PCM path | `PCM_FILT_OPT` (0x090000) = `02`; `PCM_VOL_B` / `PCM_VOL_A` = `FF` (muted); `PCM_PATH_CTL_1` (0x090003) = `EC`, `PCM_PATH_CTL_2` = `00` |
| Mono mode | the 24 writes of §5.12.1 (0x180009-0x180040, four groups starting `2F B4 25 80`) |
| Output stage again | `CLASS_H_CTL` = `1F`; 80 ms; `HP_OUT_CTL_1` (0x080000) = `10`; `HP_DETECT` (0x0D0000) = `04`, 0x0D0001 = `00` |
| Interrupts | read `INT_STATUS_1/2`; `INT_MASK_1` = `87`, `INT_MASK_2` = `07` |
| Clocking | `SYS_CLK_CTL_1` (0x010006) = `04` (internal clock from the crystal); `PAD_INT_CFG` (0x01000D) = `02` |
| Undocumented | `0x010010` = `99` (opens the test registers), `0x180000` = `45`, `0x010010` = `00` |
| Power-up | `PWDN_CTL` bit 6 cleared (serial port on); `0x010010` = `99`, `0x080032` = `20`; `PWDN_CTL` bit 4 cleared (headphone amplifier on); 10 ms; `0x080032` = `00`, `0x010010` = `00`. `PWDN_CTL` ends at `A6` |
| Sample rate | `ASP_SPRATE` (0x01000B) = the rate's code (below) |
| Volume | `PCM_VOL_A` (and `_B`, ignored: `PCM_PATH_CTL_1` has `PCM_VOL_BEQA` set) = 2 × attenuation in dB, ramped |

`ASP_SPRATE` codes written: `0` for 8, 16, 32, 64 and 128 kHz, `1` for 11.025, 22.05 and 44.1, `2`
for 12, 24 and 48, `3` for 88.2, `4` for 96, `5` for 176.4, `6` for 192 (the stock firmware's
choice). The register only knows 32 to 384 kHz; the lower rates borrow the code of their family.

What the register values mean, in short:
- `CLASS_H_CTL` = `1F`: adaptive supply for the amplifier, high-voltage mode, and **external
  VCP_FILT** (bit 0). The datasheet's example writes `1E`; every firmware of this player writes
  `1F`, so the board presumably supplies VCP_FILT itself. This bit selects the power-up and
  power-down sequences that apply (§4, §5.8).
- `PCM_PATH_CTL_1` = `EC`: soft ramp before a filter change, one volume for both channels, soft
  volume ramps, automatic mute after 8,192 static samples (both channels together).
- `PCM_FILT_OPT` = `02`: fast roll-off, low latency, high-pass filter on, no de-emphasis.
- `HP_DETECT` = `04`: the chips' headphone detection off (the player detects the jacks by GPIO).

## Changing the rate

`audio_change_rate()`: both volumes to `FF`, I2S and DMA stopped, ACODEC PLL and I2S divider set,
`ASP_SPRATE` written, ring restarted, volumes back. The chips stay powered. The datasheet asks
for `ASP_SPRATE` to be set before the serial port is enabled; it is written here with the port on.
All 15 rates nevertheless measure exact on the device (`ETUDE.md` §88).

## The firmwares compared

What each firmware writes, as far as it differs from the table above. The stock firmware (V3.9.0)
and RECHO 0.10.0 were read from their binaries; EchoPod and ReChord from their sources (GPL-3,
read for information only, nothing taken). All four use the same sequence: ReChord and EchoPod
derive from the stock firmware, and this firmware's I2C messages were checked byte for byte against
RECHO's (`ETUDE.md` §15).

| Point | Datasheet example | Stock | RECHO | EchoPod | ReChord | This firmware |
|---|---|---|---|---|---|---|
| `HP_OUT_CTL_1` | `30` (1.73 V) | **`31` (2 V)** | `10` (1 V) | `10`, or `31` as an option | `10` | `10` (1 V) |
| `CLASS_H_CTL` | `1E` | `1F` | `1F` | `1F` | `1F` | `1F` |
| `PCM_FILT_OPT` | `02` | `02`, `42`, `82`, `C2`, `22` | `02` | `02` | `02` | `02` |
| `ASP_SPRATE` | before the port is on | per rate | `01` | per rate, at the end | per rate, at the end | per rate, at the end and on the fly |
| Headphone power-up wait | 12 ms | ? | 10 ms | 10 ms | 10 ms | 10 ms |
| `0x180000` = `45` | not described | yes | yes | yes | yes | yes |
| Power-down | §5.8.1 | `PWDN_CTL` = `10` | ? | `PWDN_CTL` = `10` | `PWDN_CTL` = `10` | §5.8.1 since 0.99e (long pause and stop) |

## Choices

### 1. Output level: 1 V (kept)

`HP_OUT_CTL_1` sets the full-scale output voltage (`OUT_FS`, bits 5:4: 0.5, 1, 1.41 or 1.73 V)
and, at 1.73 V with high-voltage mode on, bit 0 lifts it to 2 V. This firmware, like RECHO and
ReChord, writes `10`: **1 V**. The stock firmware writes `31`: **2 V**, about **6 dB louder** at
the same volume setting; EchoPod offers both as a "gain" setting.

Decided: 1 V, no setting. Should a 2 V setting come later, the register may only change while the
headphone amplifier is off (`PDN_HP` set): mute, set `PDN_HP`, write `HP_OUT_CTL_1`, then the
headphone power-up of the start-up sequence again.

### 2. Digital filter: fast roll-off, low latency (kept)

`PCM_FILT_OPT` chooses the interpolation filter: bit 7 slow / fast roll-off, bit 6 phase
compensated / low latency, bit 5 non-oversampling emulation (NOS, overriding the two others). The
stock firmware's five values are exactly the five possible filters, most likely its user setting:

| Value | Filter |
|---|---|
| `02` | fast roll-off, low latency (this firmware) |
| `42` | fast roll-off, phase compensated |
| `82` | slow roll-off, low latency |
| `C2` | slow roll-off, phase compensated |
| `22` | NOS emulation |

All keep bit 1 (high-pass filter on). The change is done by the chip with a soft mute around it
(`PCM_RAMP_DOWN` set in `PCM_PATH_CTL_1`), so it can be written while playing.

Decided: `02`, no setting. Bit 2 (`PCM_WBF_EN`, wideband flatness) is meant for 192 kHz only and
must be changed with the amplifier off.

### 3. Power-down without a pop (implemented, 0.99e)

With `CLASS_H_CTL` bit 0 set (external VCP_FILT), the datasheet gives a pop-free power-down
(§5.8.1): open the test registers (`0x010010` = `99`) and write `0x080046` = `21`; mute both
channels (`PCM_PATH_CTL_1` bits 1:0); wait for the mute (150 ms); unmask `PDN_DONE`
(`INT_MASK_1` bit 0); set `PDN_HP`; wait for `PDN_DONE` in `INT_STATUS_1`; then the rest
(serial port, crystal) and the closing of the test registers.

Before 0.99e, this firmware wrote `PWDN_CTL` = `F6` at once after 10 s of pause and at the stop
(amplifier, serial port and the rest off together, GPIO2_0 at 1 first). The stock firmware,
EchoPod and ReChord write `PWDN_CTL` = `10` at the stop, which sets `PDN_HP` but also *clears* the
crystal, PLL and clock-output power-down bits.

Since 0.99e (`dac_power_down()` in `fw/src/audio.c`, called by `dac_standby()` for the long pause
and by `audio_stop()`):
- the §5.8.1 steps on both chips, except the wait for `PDN_DONE`: **these chips never raise it**.
  Test image 0.99f waited up to 1 s and read `INT_STATUS_1` all along, at five power-downs (long
  pauses with the I2S stopped; end of the playlist and switch to the USB sound card with the I2S
  running): bit 0 stayed at 0 (`INT_STATUS_1` = `10`, `XTAL_READY` only), while `PWDN_CTL` read
  `B6` (`PDN_HP` taken). A fixed **100 ms** after `PDN_HP` replaces the wait: what 0.99e did in
  practice (its 100 ms limit always ran out), with no click heard;
- `PWDN_CTL` ends at `F6` as before; `INT_MASK_1` is no longer touched;
- GPIO2_0 (jacks silenced) only once the amplifiers are off; at the stop, the I2S keeps running
  until then, so the chips have their clocks during the sequence;
- the cost: 250 ms at the long pause and at the stop.

On the device (0.99e, 2026-11-01): no click at the long pause or at the stop, nor during a run
through the 15 rates; the resume after a long pause sounded smoother (its sequence did not change:
perhaps the track). The 100 ms may be shortened later, by ear.

### Later

- `ASP_SPRATE` written with the serial port off (`PWDN_CTL` bit 6 set around it) on a change of
  rate, as the datasheet asks; no fault is known today.
- The 12 ms wait of the datasheet after the headphone power-up, instead of 10 ms.
